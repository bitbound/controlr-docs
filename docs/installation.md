The recommended way to install ControlR is using Docker Compose.

Prerequisites are listed in the [Getting Started guide](/docs/getting-started).

## Quick Start

### Using Environment Variables

```bash
wget https://raw.githubusercontent.com/bitbound/ControlR/main/docker-compose/docker-compose.yml
# Set environment variables for sensitive values or create a .env file
ControlR_POSTGRES_USER="controlr_admin" \
ControlR_POSTGRES_PASSWORD="<secure-password>" \
ControlR_ASPIRE_BROWSER_TOKEN="<secure-token>" \
sudo docker compose up -d
```

### Using Docker Secrets

For production deployments with sensitive credentials:

```bash
wget -O docker-compose.yml https://raw.githubusercontent.com/bitbound/ControlR/main/docker-compose/docker-compose-secrets.yml
# Create secret files and set appropriate permissions (chmod 600)
sudo docker compose -f docker-compose-secrets.yml up -d
```

## Verify Installation

After the containers start, verify that ControlR is running:

```bash
curl http://127.0.0.1:5120/health
```

You should receive: `Healthy`

The ControlR web interface should be available at `http://your-server:5120` (or `https://your-domain` if you configured a reverse proxy with HTTPS).

## Installing the Agent

Once the server is running, install the agent on devices you want to manage. Agents are available for Windows, macOS, and Linux.

### One-Click Deploy (Recommended)

The easiest way to install an agent is from the **Deploy** page. Navigate to Deploy in the ControlR web interface and follow these steps:

1. **Create an installer key** (or select an existing one). Keys can be **usage-based** (expire after a set number of uses), **time-based** (expire at a specific time), or **persistent** (never expire).
2. **Select the target operating system** for the device.
3. **Optionally add device tags** to categorize the device on registration.
4. **Copy the generated script** using the copy button and paste it into the target device's terminal or PowerShell.

The script downloads the appropriate installer, runs it with all the correct arguments, and registers the device automatically. You can also choose to save the installer key secret when you create it. This is the only time the secret is displayed.

### Manual Installation

The one-liner scripts generated by the Deploy page serve as good reference for what a manual installation looks like. Installers are downloaded directly from the ControlR server and run with the appropriate arguments for your platform.

#### Linux (via systemd)

```bash
wget https://your-server/downloads/linux-x64/ControlR.Agent.Installer
chmod +x ControlR.Agent.Installer

sudo ./ControlR.Agent.Installer install \
  --server-uri https://your-server.example.com \
  --tenant-id <your-tenant-guid> \
  [--instance-id my-server] \
  [--device-tags <tag-guid1>,<tag-guid2>] \
  [--installer-key-secret <key-secret>] \
  [--installer-key-id <key-guid>] \
  [--device-id <existing-device-guid>]
```

To uninstall:
```bash
sudo ./ControlR.Agent.Installer uninstall [--instance-id my-server]
```

#### macOS

```bash
wget https://your-server/downloads/osx-arm64/ControlR.Agent.Installer
chmod +x ControlR.Agent.Installer

sudo ./ControlR.Agent.Installer install \
  --server-uri https://your-server.example.com \
  --tenant-id <your-tenant-guid> \
  [--instance-id my-mac] \
  [--device-tags <tag-guid1>,<tag-guid2>] \
  [--installer-key-secret <key-secret>] \
  [--installer-key-id <key-guid>] \
  [--device-id <existing-device-guid>]
```

To uninstall:
```bash
sudo ./ControlR.Agent.Installer uninstall [--instance-id my-mac]
```

#### Windows

```powershell
Invoke-WebRequest -Uri "https://your-server/downloads/win-x64/ControlR.Agent.Installer.exe" -OutFile "ControlR.Agent.Installer.exe"

.\ControlR.Agent.Installer.exe install `
  --server-uri "https://your-server.example.com" `
  --tenant-id "<your-tenant-guid>" `
  [--instance-id "my-pc"] `
  [--device-tags "tag-guid1,tag-guid2"] `
  [--installer-key-secret "<key-secret>"] `
  [--installer-key-id "<key-guid>"] `
  [--device-id "<existing-device-guid>"]
```

To uninstall:
```powershell
.\ControlR.Agent.Installer.exe uninstall --instance-id "my-pc"
```

#### Repair Desktop Client (Internal Use)

The installer includes a `repair-desktop` command that re-installs the desktop client from the current agent bundle. This command is intended for internal troubleshooting and is not part of the standard installation workflow:

```bash
sudo ./ControlR.Agent.Installer repair-desktop [--instance-id my-server]
```

#### Installer Behavior

Each installer does the following:

**Linux**: Extracts the agent bundle to `/usr/local/bin/ControlR`, generates systemd service files for the agent and desktop client, then enables and starts the agent service.

**macOS**: Installs the agent to `/Library/Application Support/ControlR/<instanceId>` and the desktop client to `/Applications/ControlR.app`, installs launchd daemons for the agent, desktop client, and self-updater, then starts the agent service.

**Windows**: Installs to `C:\Program Files\ControlR\<instanceId>`, creates a Windows Service for the agent, and starts it.

When an installer key is provided (`--installer-key-secret` / `-ks`), the installer also creates the device registration on the server. If `AllowAgentsToSelfBootstrap` is `true` in your server configuration, you can omit the installer key and the device will self-register.

### Installer Arguments Reference

| Argument | Required | Description |
|----------|----------|-------------|
| `--server-uri` (`-s`) | Yes | URL of the ControlR server (e.g., `https://controlr.example.com`) |
| `--tenant-id` (`-t`) | Yes | GUID of the tenant this agent belongs to |
| `--instance-id` (`-i`) | No | Multi-instance identifier. Useful when running multiple agents on the same machine |
| `--device-tags` (`-g`) | No | Comma-separated list of tag GUIDs to assign to the device |
| `--installer-key-secret` (`-ks`) | No | Secret of an installer access key for device registration |
| `--installer-key-id` (`-ki`) | No | GUID of a specific installer key to use |
| `--device-id` (`-d`) | No | GUID of an existing device to associate with this installation |

The CLI option names are lowercase-kebab (`--server-uri`, `--tenant-id`, etc.). PowerShell accepts the same flag names as shown above; the `System.CommandLine` parser does not auto-translate PascalCase aliases.

## Configuration

ControlR is configured primarily through environment variables in your Docker Compose file. See [Configuration](/docs/configuration) for the full list of options.

Key settings:

- `ControlR_AppOptions__EnablePublicRegistration`: Allow self-registration (default: `false`)
- `ControlR_AppOptions__AllowAgentsToSelfBootstrap`: Allow agents to register without installer keys (default: `false`)
- `ControlR_AppOptions__RequireUserEmailConfirmation`: Require email confirmation for new accounts (default: `false`)
